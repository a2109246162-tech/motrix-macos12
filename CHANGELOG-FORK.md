# Fork changes — macOS 12 compatibility edition

Base: upstream `agalwood/Motrix` v2.4.2 (commit `c601dcf`).
This edition contains **no ED2K-related source changes**.

| Area | File(s) | Change | Reason |
| --- | --- | --- | --- |
| Packaging metadata | built `Info.plist` inside `Motrix.app` | `LSMinimumSystemVersion`: `13.0` → `12.0` | Official 2.4.2 refuses to launch on macOS 12. |
| Mach-O metadata | 18 bundled executables/dylibs | `LC_BUILD_VERSION.minos`: `13.0` → `12.0` (via `macos12-patch/patch_minos.py`) | LaunchServices and dyld check the binary's minimum OS version, not only Info.plist. |
| macOS 13 symbol: ServiceManagement | `libmotrix_mac12_stub.dylib` (built from `macos12-patch/stub.m`) | Replaces the framework dependency that referenced `SMAppService` | `SMAppService` only exists on macOS 13+. Login-item registration is unavailable on macOS 12. |
| macOS 13 symbol: VideoToolbox | `libmotrix_vt_stub.dylib` (built from `macos12-patch/stub_vt.c`) | Re-exports VideoToolbox and defines `kVTCompressionPropertyKey_ReferenceBufferCount` | Constant was introduced in macOS 13. |
| macOS 13 symbol: AppKit | `libmotrix_AppKit_stub.dylib` (generated by `macos12-patch/fix_loop.py`) | Re-exports AppKit and defines `NSPreviewRepresentingActivityItem` | Class was introduced in macOS 13. |
| Code signatures | `Motrix.app` plus standalone helpers `MotrixSafariRegistrar`, `motrix-native-host`, `motrix-finalize-fs`, `MotrixSafariBootstrap` | Ad-hoc re-signing after binary patching | Unre-signed helpers cause `spawn Unknown system error -85` and "任务暂不可用". |
| Documentation | `README-MACOS12.md`, `ATTRIBUTION.md`, this file | Added | Explain usage, attribution and exact changes. |

## Verification

- macOS 12.7.6 (Intel Xeon E3-1505M v5): app launches, dashboard shows engine ready, aria2 v1.37.0 RPC works, no new error logs.
- The upstream HTTP/HTTPS/FTP/BitTorrent/Magnet behaviour is unchanged.
